## Problem Statement

Two issues with client→upstream request header mapping:

### 1. `forward_request_headers_map` lacks protocol-aware correlation mapping

`auth.rs` currently does blind reciprocal mapping: `x-request-id ↔ x-claude-code-session-id`. It sends BOTH headers regardless of upstream protocol, relying on "upstream ignores what it doesn't understand." But it's missing:

- **Anthropic upstream**: `X-Client-Request-Id → x-claude-code-session-id`
- **OpenAI upstream**: `x-claude-code-session-id → X-Client-Request-Id`

And it incorrectly **forwards `x-request-id` to upstream** — `x-request-id` is generated by the upstream, the proxy should map it, not forward it.

### 2. `build_interactions_headers_map` has unnecessary `x-claude-code-session-id → X-Client-Request-Id`

Gemini is a stateful protocol — session continuity is via `previous_interaction_id` in request body. The `X-Client-Request-Id` header is irrelevant for Gemini. The mapping should be removed.

## Proposed Solution

### Part A: Make `forward_request_headers_map` protocol-aware

Add a `protocol: Protocol` parameter. Mapping rules:

**Anthropic upstream:**
| Client header | Upstream header |
|--------------|-----------------|
| `x-request-id` | `x-claude-code-session-id` (mapped, not forwarded) |
| `X-Client-Request-Id` | `x-claude-code-session-id` (mapped, not forwarded) |
| `x-claude-code-session-id` | `x-claude-code-session-id` (passthrough) |

**OpenAI upstream:**
| Client header | Upstream header |
|--------------|-----------------|
| `x-request-id` | `X-Client-Request-Id` (mapped, not forwarded) |
| `x-claude-code-session-id` | `X-Client-Request-Id` (mapped, not forwarded) |
| `X-Client-Request-Id` | `X-Client-Request-Id` (passthrough) |

`x-request-id` is **never** forwarded as-is to any upstream.

### Part B: Remove Gemini `x-claude-code-session-id → X-Client-Request-Id`

Remove lines 2502-2510 from `build_interactions_headers_map`. Gemini is stateful — correlation is via `previous_interaction_id`, not HTTP headers.

## Scope

### In Scope
- Add `protocol: Protocol` parameter to `forward_request_headers_map` and `forward_request_headers`
- Implement protocol-aware correlation mapping in `forward_request_headers_map`
- Update all call sites (OpenAiHandler, AnthropicHandler)
- Remove `x-claude-code-session-id → X-Client-Request-Id` from `build_interactions_headers_map`
- Add `X-Client-Request-Id` to `is_auth_header` or `should_forward_request_header` exclusion (it's a correlation header, not an auth header — should be handled explicitly, not forwarded blindly)

### Out of Scope
- Response header mapping (already correct)
- Interactions handler changes beyond removing the Gemini mapping
